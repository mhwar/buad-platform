# قواعد تصميم منصة بُعد

أسلوب المنصة يثبت بثلاثة أشياء: مكوّن مشترك واحد لكل حالة، ورموز (tokens) بدل الألوان والقيم المكتوبة باليد، واختبارات تمنع الرجوع. أي مشكلة تصميم تُحلّ في المكوّن المشترك، فتسري على كل الصفحات، لا في صفحة واحدة.

## الرموز (`apps/web/src/index.css`)

| الرمز | المعنى | مثال |
| --- | --- | --- |
| `brand` | الإجراء الأساسي (حبر على الفاتح، فاتح على الداكن) | الزر الأساسي |
| `accent` (برتقالي) | «أنت هنا»، التقدم، الإبراز | القسم النشط في الشريط الجانبي |
| `surface` / `canvas` | سطح البطاقة / خلفية الصفحة | — |
| `ink` / `muted` / `line` | النص / النص الثانوي / الحدود | — |
| `success` · `warning` · `danger` | معنى الحالة: نجح، يحتاج انتباهاً، خطأ أو حذف | `text-danger-ink`، `bg-warning-soft` |
| `-soft` / `-ink` / `-line` / بلا لاحقة | خلفية / نص وأيقونة (تباين AA) / حدّ / تعبئة | `bg-success-soft text-success-ink` |
| `rounded-card` · `rounded-control` | زاوية البطاقة / زاوية الحقل والزر | — |
| `shadow-card` · `shadow-raised` | ظل البطاقة / ظل القوائم والنوافذ | — |

- **لا ألوان خام:** لا `red-*` ولا `amber-*` ولا `emerald-*` ولا `#hex` في الصفحات. الرمادي `slate-*` مسموح، لأنه مربوط بالرمادي المحايد.
- **الاستثناء:** صفحات الطباعة والموقع العام.
- **الوضع الداكن:** يأتي من الرموز نفسها. لا حاجة إلى `dark:` مع ألوان الحالة.

## المكوّنات: أيّها لأي حالة (`components/`)

| الحالة | المكوّن |
| --- | --- |
| عنوان الصفحة وإجراؤها | `PageHeader`: عنوان واحد، وزر أساسي واحد على الأكثر، والباقي في «⋯» |
| رقم بارز (مؤشر) | `StatTile` |
| تبديل أقسام داخل صفحة | `Segmented`. للتصفية بالعدد: `Pills`. لعرض قائمة/لوحة/جدول: `LayoutToggle` |
| فلاتر قائمة | `FilterBar` (ورقة سفلية على الجوال)، وقيمها في الرابط |
| جدول بيانات | `DataTable`: جدول على الحاسوب، وبطاقات معنونة على الجوال |
| نافذة | `Dialog` + `DialogActions` (ورقة سفلية على الجوال، حبس التركيز) |
| تأكيد قبل إجراء | `confirmAction`. الزر يسمّي الإجراء («حذف نهائياً»)، لا «موافق» |
| رسالة بعد حفظ | `toast` |
| تنبيه داخل الصفحة | `Notice` |
| حالة فارغة | `EmptyState` |
| تحميل / خطأ قسم | `Skeleton` و`SectionBoundary` |
| حالة سجل | `Badge` بلون الحالة، و`Stamp` للأختام (مغلق، موزّع) |

## قواعد ثابتة

1. **حالة الصفحة في الرابط:** التبويب والفلاتر والفترة. التحديث والرجوع لا يضيّعان المكان.
2. **حجم النص:** لا نص أصغر من 12 بكسل، ولا أهداف لمس أصغر من 44 بكسل على الجوال.
3. **لا تمرير جانبي** على أي صفحة وبأي عرض.
4. **التواريخ:** بالصيغة العربية دائماً (`day()`)، ولا `YYYY-MM-DD` ظاهرة للمستخدم.
5. **المال:** بـ`sar()` و`moneyShort()`، والأرقام بخط جدولي (`tabular-nums`).
6. **الإتاحة:**
   - لكل زر أو أيقونة اسم مقروء.
   - النوافذ معرّفة كحوارات.
   - الصفحة تعمل كاملة بلوحة المفاتيح.
   - أول عنصر في الصفحة رابط «تخطَّ إلى المحتوى».
7. **صفحة جديدة:** تُبنى من المكوّنات أعلاه. إن احتجتم شكلاً غير موجود، أضيفوه إلى `components/` بدل كتابته داخل الصفحة.

## ما يحمي القواعد

| الفحص | ماذا يمنع | أين |
| --- | --- | --- |
| إتاحة WCAG 2.1 A/AA (axe-core) | أي مخالفة على الصفحات الرئيسية، بالوضعين الفاتح والداكن | `e2e/tests/a11y.spec.ts` |
| فحص الجوال | التمرير الجانبي، والنص تحت 12 بكسل، والتواريخ الخام، والجداول المضغوطة (11 صفحة) | `e2e/tests/smoke.spec.ts` |
| قواعد التصميم | الألوان الخام والـ hex في الصفحات، والنص تحت 12 بكسل في الكود | `apps/web/src/design-rules.test.ts` |
| المكوّنات المشتركة | سلوك النوافذ والتأكيد والجداول والحالة في الرابط | `components/*.test.tsx` و`lib/url-state.test.tsx` |

كل هذه الفحوص تعمل قبل كل نشر، فلا يصل إلى المنصة ما يكسر القواعد. وتعرض صفحة «الإعدادات ← الجودة والامتثال» البنود وحالتها. كل تصدير أو طباعة يُسجَّل في «سجل النشاط».
